## Условие задания

Для лабораторной работы №3 оформить иерархию классов как многофайловую программу (если не сделано).
Разместить объявление и определение каждого класса в отдельных файлах: ClassName.h и ClassName.cpp.
Собрать код в:

- статическую библиотеку (liblab3.a / lab3.lib);
- динамическую библиотеку (liblab3.so / lab3.dll + lab3.lib для импорта на Windows).

Написать две тестовые программы, каждая из которых использует одинаковый клиентский код, но линкуется
с разными библиотеками. Сборку всех компонентов (библиотек и тестовых программ) выполнить вручную, с
использованием прямых вызовов компилятора (g++/clang++). Использование систем автоматической сборки
(make, CMake, ninja и др.) не допускается.

## Сборка вручную

Команды из build_static.bat. Каждая делает одно действие, системы сборки не используются.

```console
g++ -std=c++14 -Wall -Wextra -pedantic -Iinclude -c src\Polynomial.cpp -o build\Polynomial.o
ar rcs build\liblab3.a build\Polynomial.o
g++ -std=c++14 -Wall -Wextra -pedantic -Iinclude -c client\client.cpp -o build\client.o
g++ -static build\client.o build\liblab3.a -o build\test_static.exe
```

| Команда | Что делает |
|---------|------------|
| `g++ -c` | компилирует один `.cpp` в объектный файл `.o`: машинный код без точки входа; `-Iinclude` — где искать `Polynomial.h` |
| `ar rcs` | упаковывает объектные файлы в архив — статическую библиотеку; `r` — добавить файл, `c` — создать архив, `s` — записать индекс символов |
| `g++ ... -o` без `-c` | линкует: подставляет в клиент нужный код из библиотеки и создаёт исполняемый файл |

## Что такое статическая библиотека

Статическая библиотека — это архив объектных файлов. При линковке из неё берутся те объектные файлы,
которые нужны клиенту, и их код **копируется внутрь** исполняемого файла. Поэтому:

- готовый `test_static.exe` запускается без библиотеки: `liblab3.a` нужна только при сборке;
- в файле `.a` лежит один объектный файл `Polynomial.o`; это проверяется командой `ar t build\liblab3.a`;
- размер exe больше (в нём копия кода класса и стандартной библиотеки C++); если несколько программ
  используют библиотеку, в каждой своя копия;
- чтобы обновить код класса, нужно пересобрать и программу.

Флаг `-static` при линковке дополнительно встраивает в exe библиотеки компилятора MinGW (`libstdc++`
и др.): так программа запускается и на компьютере, где компилятор не установлен. К самому понятию
«статическая библиотека» это не относится: оно описывает способ подключения `liblab3.a`.

## Клиентский код

client.cpp использует только открытый интерфейс из Polynomial.h и не знает, какая библиотека под ним
подключена; поэтому во второй части он останется тем же. Проверки разбиты на пять групп:

1. создание многочленов и значения; счётчик существующих многочленов — **статическое поле**, которое
   хранится в библиотеке; деструктор уменьшает его тоже в коде библиотеки;
2. корни: два, один, ни одного, любое число; счётчик поисков корней вырос на число вызовов;
3. операции `+`, `-`, `*`, `/`, `++`, вывод в поток;
4. сравнения многочленов в точке x₀ — ещё одно статическое поле библиотеки;
5. исключения: их **бросает код библиотеки**, а **ловит клиент** (`std::invalid_argument`,
   `std::overflow_error`) — это важно для динамической библиотеки во второй части.

## Проверка

- Сборка `g++ -std=c++14 -Wall -Wextra -pedantic` — без ошибок и предупреждений.
- `test_static.exe` — 23 проверки из 23, код возврата 0.
- Чувствительность клиента проверена на испорченной копии библиотеки (в `valueAt` знак `+ c` заменён на
  `- c`): клиент сообщает о 2 проваленных проверках из 23 и возвращает код 1.
- Зависимости `test_static.exe` (`objdump -p`): только системные библиотеки Windows (`KERNEL32.dll`,
  `api-ms-win-crt-*.dll`); собственной `lab3`-библиотеки среди них нет.
